# ИИ-администратор: портфолио с живыми демо

Сайт-портфолио, на котором лежат не скриншоты, а четыре рабочих бота: типография,
автосервис, стоматология и фитнес. Каждый считает цену по прайсу, отвечает клиенту
и складывает заявку в базу.

## Зачем это

В подрядных продажах портфолио решает больше, чем описание услуг. Показать живой
чат, где бот сам считает смету и честно говорит «этого я не знаю», можно за минуту
и без звонка. Поэтому портфолио здесь это работающее приложение, а не PDF с кейсами.

Клиентских логотипов нет намеренно: первые внедрения запускаются сейчас, и подставлять
чужие работы вместо своих я не буду. Всё, что на сайте, можно проверить руками.

## Что внутри

- **Разбор вопроса без нейросетей.** `app/nlu.py` достаёт из живого текста услугу,
  тираж, срочность и телефон. Понимает «5 тыс», «тысяча штук», «срочно к утру».
- **Расчёт по правилам прайса.** `app/pricing.py`: цена из каталога, скидка от объёма,
  наценка за срочность, доставка. Один и тот же код считает и бот, и тесты.
- **Диалог как конечный автомат.** `app/dialog.py` спрашивает только то, чего не хватает
  для сметы, и не задаёт вопросов ради вопросов.
- **Заявки.** `app/storage.py` на SQLite: сессии, сообщения, заявки, выгрузка в CSV.
- **Фронтенд без фреймворков.** Чистый JS, никаких CDN: страница работает и без интернета.

## Две версии одного продукта

| Версия | Где работает | Зачем |
|---|---|---|
| Серверная (`app/`) | FastAPI + SQLite | бот для клиента: заявки в общей базе, админка, выгрузка CSV |
| Статическая (`static_site/`) | GitHub Pages, любой хостинг статики | портфолио, которое можно открыть по ссылке сразу: движок считает в браузере |

Правила расчёта в обеих версиях одни и те же, каталог прайсов один. Совпадение проверяет
`tests/test_parity.py`: он гоняет матрицу случаев (все услуги, все тиражи, обычный и срочный
заказ, больше сотни комбинаций) через Python и через JS и падает, если цены разошлись.

## Публикация на GitHub Pages

Всё готово, нужен только твой аккаунт GitHub. Порядок:

```bash
# 1. создать пустой репозиторий на github.com, например ai-admin
git remote add origin https://github.com/ТВОЙ_ЛОГИН/ai-admin.git
git branch -M main
git push -u origin main
```

2. В репозитории открыть `Settings` → `Pages` → в блоке `Build and deployment`
   выбрать `Source: GitHub Actions`.
3. Пуш в `main` сам запускает `.github/workflows/pages.yml`: тесты, сборка статики,
   публикация. Через минуту сайт живёт на `https://ТВОЙ_ЛОГИН.github.io/ai-admin/`.

Ничего доустанавливать не нужно: статика целиком в `static_site/`, собирается
скриптом `scripts/build_static.py` и не требует Python на хостинге.

Что важно знать до публикации:

- Pages для публичного репозитория бесплатен, для приватного нужен платный аккаунт GitHub.
- Pages отдаёт только статику. Поэтому заявки в статической версии хранятся в браузере
  (раздел `Заявки`, выгрузка CSV работает). Общая база заявок это серверная версия,
  её ставят на Vercel, Render или свой сервер.
- Адрес вида `логин.github.io/ai-admin` клиенту показывать нормально, это не временная ссылка.

### Почему не Vercel

Vercel умеет Python, но у него файловая система только на чтение и `/tmp` живёт до перезапуска
функции. SQLite в такой среде теряет заявки при каждом холодном старте, то есть главная
ценность бота пропадает. Vercel хорош, когда заявки уходят в Telegram или в почту, и мы
к этому придём: это следующая версия, отдельным шагом.

## Запуск

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
# или
make run
```

Открыть: `http://localhost:8000`

## Тесты

```bash
make test
```

19 тестов: разбор вопросов, скидки от тиража, срочность, бесплатные услуги,
рендер всех страниц, создание заявки через API и выгрузка в CSV. Отдельный тест
проверяет, что в текстах интерфейса нет длинных тире.

## Что где

| Путь | Что делает |
|---|---|
| `/` | портфолио: демо, устройство, условия |
| `/demo/typography` | бот типографии |
| `/demo/avtoservis` | бот автосервиса |
| `/demo/stomatology` | бот клиники |
| `/demo/fitness` | бот фитнес-клуба |
| `/admin` | заявки, собранные ботами |
| `/admin.csv` | выгрузка заявок |
| `POST /api/chat` | диалог: `{slug, session_id, text}` |
| `GET /api/leads` | заявки в JSON |
| `/health` | проверка живости |

## Проверка за минуту

1. Открыть демо типографии и написать «визитки 500».
2. Написать «визитки 5000»: цена за штуку упадёт, это скидка от объёма.
3. Написать «листовки 1000 срочно»: появится наценка за срочность.
4. Написать телефон: заявка появится в `/admin` и в CSV.

### Сборка статики вручную

```bash
python3 scripts/build_static.py   # результат в static_site/
python3 -m http.server 8081 --directory static_site   # посмотреть локально
```

## Структура

```
app/
  catalog.py    прайсы четырёх ниш и их характеры
  nlu.py        разбор живого вопроса
  pricing.py    смета по правилам
  dialog.py     сценарий диалога
  storage.py    SQLite: сессии, сообщения, заявки
  main.py       FastAPI: страницы и API
  templates/    HTML на Jinja2, стили внутри страницы
  static/       demo.js, без сборки и без CDN
scripts/
  build_static.py   сборка статической версии для GitHub Pages
  templates/        шаблоны портфолио, демо и админки для статики
static_site/        готовая статика: index, 4 демо, админка, движок, каталог
tests/              pytest, включая сверку JS и Python
.github/workflows/  публикация на Pages: тесты, сборка, деплой
```
